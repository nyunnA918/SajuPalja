## 🚀 설치 방법

1. 키트 폴더 전체를 호스팅에 업로드
2. `data/` 폴더에 쓰기 권한 부여 (`chmod 755 data/`)
3. 브라우저에서 `https://your-domain.com/install.php` 접속
4. 3단계 마법사:
   - **Step 1**: DB 정보 + 테이블 prefix (예: `milk_`)
   - **Step 2**: 관리자 ID/비밀번호 + 사이트 이름 + 기본 테마
   - **Step 3**: 완료
5. 보안을 위해 `install.php` + `install/` 폴더 삭제
6. 사이드바 하단 자물쇠 → 관리자 로그인 → `/admin/` 에서 사이트 꾸미기

## 📱 PC vs 모바일 자동 전환

**모바일 (≤ 768px):**
- 좌측 사이드바 자동 숨김
- 상단에 작은 사이트명 바
- 하단에 5칸 탭바: 핀 게시판 4개 + 더보기
- 더보기 → 풀스크린 드로어 (전체 메뉴 + 로그인)

**PC (≥ 769px):**
- 좌측 사이드바 (브랜드 + 메뉴 그룹 + 게시판 + 로그인)
- 본문은 우측 그리드

같은 메뉴 데이터 한 벌로 양쪽이 동작 — 관리자가 게시판마다 "모바일 핀(📌)" 체크박스만 켜면 그 게시판이 자동으로 모바일 하단 탭에 노출됨. 핀 4개를 넘으면 첫 4개만, 부족하면 첫 자리에 "홈"이 자동 채워짐.

## ✨ 핵심 설계 — Prefix 자동 치환

```php
// 스킨/블록 작성자가 쓰는 코드
qAll("SELECT * FROM {post} WHERE po_bo_id = ?", [$bo_id]);
//                          ↑
//                  자동으로 {prefix}_post 로 변환
```

설치 시 정한 prefix가 모든 SQL에 자동으로 붙음. 다른 사람이 만든 스킨을 가져와도 자동으로 본인 prefix 따라감.

## 🧩 메인 페이지 블록 옵션 가이드

admin → 메인 페이지에서 각 블록의 **옵션(JSON)** 칸에 입력하는 값. 모든 키는 선택이며,
비워두면 아래 기본값이 사용됨. 형식은 표준 JSON (큰따옴표 사용).

예) `{"limit": 6, "title": "최근 일기"}`

### `recent` — 최근 글
| 키 | 타입 | 기본값 | 설명 |
|---|---|---|---|
| `title` | string | `"최근 글"` | 블록 제목 |
| `limit` | int (1–20) | `6` | 표시할 글 개수 |
| `boards` | int[] | (전체) | 특정 게시판 ID 배열만 노출. 예: `[2,5]` |

### `profile` — 프로필 카드
| 키 | 타입 | 기본값 | 설명 |
|---|---|---|---|
| `show_banner` | bool | `true` | 상단 배너 노출 |
| `show_social` | bool | `true` | 소셜 링크 아이콘 노출 |
| `show_note` | bool | `true` | 자기소개 메모 노출 |

### `guestbook` — 방명록 미리보기
| 키 | 타입 | 기본값 | 설명 |
|---|---|---|---|
| `title` | string | `"방명록"` | 블록 제목 |
| `limit` | int (1–20) | `4` | 미리보기 개수 |
| `show_more_link` | bool | `false` | "더 보기" 링크 노출 |

### `friends` — 링크/친구 목록
| 키 | 타입 | 기본값 | 설명 |
|---|---|---|---|
| `title` | string | `"Links"` | 블록 제목 |
| `limit` | int (1–100) | `50` | 표시 개수 |

### `tags` — 태그 모음
| 키 | 타입 | 기본값 | 설명 |
|---|---|---|---|
| `title` | string | `"태그"` | 블록 제목 |
| `tags` | string[] | (자동) | 직접 지정할 태그 배열. 예: `["일상","후기"]` |

### `custom-html` — 자유 HTML
| 키 | 타입 | 기본값 | 설명 |
|---|---|---|---|
| `title` | string | `""` | 블록 제목 (비우면 제목 없음) |
| `html` | string | `""` | 삽입할 HTML 문자열 |

> 옵션 키는 각 블록 파일(`skins/main/default/blocks/*.php`) 상단에서 직접 확인·추가할 수 있음.

## 🖼 게시글 이미지 — 업로드 + 외부 URL

글쓰기/수정 화면의 **이미지 첨부**(파일) 아래에 **외부 이미지 URL** 칸이 있어요.

- 다른 곳(트위터, imgur, 디스코드 등)에 올린 이미지 주소를 넣고 Enter 또는 "추가"
- 여러 줄 붙여넣기 하면 한 번에 여러 장 추가 (업로드 파일과 합쳐 최대 20장)
- 각 썸네일의 **본문 삽입** 버튼 → 커서 위치에 이미지가 들어감 (업로드 이미지와 동일)
- 소스 모드에서 `[img:https://...]` 를 직접 써도 렌더됨
- 첫 번째 이미지(업로드든 URL이든)가 목록 썸네일로 쓰임

## 🔔 푸시 알림 (Web Push)

방문자가 **댓글·방명록**을 남기면 등록해 둔 폰/PC 브라우저로 알림이 와요. 앱을 닫아둬도 도착.

**조건**
- 사이트가 **HTTPS** 여야 함 (서비스워커 필수 조건)
- PHP openssl 확장 (대부분의 호스팅에 기본 포함). PHP 7.3 이상이면 알림 본문까지 암호화 전송, 그 미만이면 "깨우기" 방식(서비스워커가 내용을 따로 받아옴)
- 외부 라이브러리 없음 — `lib/push.php` 가 VAPID 서명과 RFC 8291 암호화를 직접 처리

**설정 방법**
1. 관리자 → **알림** 탭 → "이 기기에서 알림 받기" → 브라우저 알림 허용
2. "테스트 알림" 으로 확인
3. 기기마다 1회씩 등록 (PC Chrome, 폰 등). 등록된 기기 목록에서 삭제 가능

**iPhone / iPad**: Safari 탭에서는 안 되고, 공유 → **홈 화면에 추가** 한 앱 안에서 관리자 → 알림 탭에 들어가 등록해야 해요 (iOS 16.4+).

**관련 파일**: `sw.js`(사이트 루트, 푸시 전용 — fetch 캐시 없음), `ajax/push.php`, `lib/push.php`, `lib/notify.php`, `data/.vapid.php`(자동 생성 키 — 지우면 모든 기기 재등록 필요)

알림은 `{notify}` 테이블에도 남아 관리자 → 알림 탭에서 볼 수 있고, 사이드바/드로어의 "관리자 설정" 옆에 안 읽은 개수 뱃지가 떠요.

## 👣 방문자 카운터

사이드바 하단(PC) / 전체 메뉴 하단(모바일)에 **Today · Total** 표시.

- 같은 브라우저는 하루 1회만 집계 (쿠키 `hp_vd`), 관리자 로그인 상태와 검색 봇 제외
- 관리자 → 사이트 정보 → **방문자 카운터**: 표시 on/off, 최근 14일 그래프, 누적 보정값(옛 홈페이지 카운터 이어받기)
- 저장: `{visit}` (날짜별 1행)

## 🛡 긴 글 안전장치

본문 글자 수 제한은 **없음** (DB `LONGTEXT`). 그래도 몇만 자 글이 "가끔 저장 안 됨" 이 생기는 건 대부분 호스팅 쪽 제한(mod_security 기본 128KB, `post_max_size`) 때문이라 다음 장치를 넣어뒀어요.

| 장치 | 동작 |
|---|---|
| 분할 전송 | 본문이 60KB 를 넘으면 `ajax/chunk.php` 로 48KB 씩 나눠 올린 뒤 토큰만 폼에 담아 전송 (`spa.js` + `hp_post_content_field()`) |
| 임시저장 | 글쓰기/수정 화면에서 3초마다 브라우저(localStorage)에 저장. 다시 들어오면 "복구" 배너. 발행 성공 시 자동 삭제 (`js/draft.js`) |
| 전송 실패 시 폼 유지 | 413/403/500 등 오류 응답이 와도 화면을 갈아끼우지 않고 하단에 오류만 표시 — 작성 중이던 글이 사라지지 않음 |
| 세션 유지 | 글쓰기 중 5분마다 `ajax/ping.php` 호출. 로그인이 풀리면 즉시 경고 |
| 진단 | 관리자 → 사이트 정보 → **서버 환경** 에서 `post_max_size` 등 확인 |
